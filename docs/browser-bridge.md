# ChatGPT browser bridge prototype

Grace Planner now defaults to `ChatGPT browser`. The site does not call the OpenAI API in this mode and never falls back to paid inference. The existing API path is available only after explicitly selecting `OpenAI API (separate billing)`.

The companion Chrome Manifest V3 extension pairs one Grace chat with one existing, signed-in ChatGPT tab. The user selects the Grace Plan conversation that already contains the approved PDF and workflow references, selects Instant in ChatGPT, then explicitly pairs it in the extension popup. Instant is confirmed by the user, not programmatically guaranteed after later changes in ChatGPT. The extension submits new messages through the visible composer, uploads the provided files through the normal file input, waits for a completed assistant response, mirrors its visible answer, and attempts to transfer genuine PDF bytes from visible output links. Pairing does not import or merge older histories. The ChatGPT conversation is retained.

This is a browser UI integration, not an official hosted ChatGPT API entitlement, a remote MCP server, or a quota workaround. MCP/GPT Actions expose external tools to ChatGPT in the opposite direction. Ordinary text, file uploads, images, data analysis, model access, and verification retain their normal account restrictions. Phones and browsers without Chrome extension support cannot use this prototype.

Installation instructions are included in `/grace-chatgpt-bridge.zip` and in the site's Connect ChatGPT dialog. Both tabs must remain open in the same Chrome profile. Pairings are session-scoped and must be re-established after restarting Chrome. Requests are serialized per paired tab. A dispatched request is never automatically resent. If a tab closes, generation times out, or PDF retrieval fails, the original conversation remains the source of truth; open it before retrying.

Permissions are restricted to `https://chatgpt.com/*` and `https://graceplanner.vercel.app/*`, with extension storage only. No cookie-reading, debugger, native messaging, broad host access, API keys or password fields are requested. The bridge refuses a signed-out tab, existing drafts, an already-generating response, known browser-verification frames and share pages. It exposes no arbitrary script execution or arbitrary network-fetch command. PDF retrieval follows only visible output links on permitted ChatGPT file origins and verifies the PDF signature. All files stay in the user's browser and ChatGPT; the bridge does not upload them to the Grace API.

Up to eight image files are transferred individually; larger sets are packed into one ZIP containing every source path. Limits are 40 MiB per bridge file and 120 MiB aggregate input, alongside any stricter ChatGPT limits. PDF transfer is limited to 25 MiB; larger or inaccessible outputs must be opened in ChatGPT. ChatGPT DOM changes can require adapter updates. The DOM adapter was prepared against the current visible composer and upload controls; the signed-in response and PDF flow still require end-to-end verification.

Validation: unit checks cover strict origins, invalid files, the signed-out guard, omission of hidden reasoning details, preservation of all files in a ZIP, completion semantics, no API call, and extension permission scope. The complete existing suite and production build pass. A live test send was rejected by automatic browser approval review because the ChatGPT tab was unauthenticated. Secure browser-auth filling subsequently returned `locator_invalid`; no credential was entered or persisted by the project. Do not claim a verified signed-in bridge until this prerequisite is resolved and the actual extension flow has been tested.
