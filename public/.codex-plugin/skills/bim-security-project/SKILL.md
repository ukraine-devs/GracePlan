# Grace Plan — полный проектный цикл

Работай по пользовательским исходникам и этапам обобщенного регламента. Создавай конкретные проверяемые файлы, сохраняя связь фото → помещение → объект → инженерная точка → трасса → расчет → смета → лист.

## Сначала определи режим

- Новый объект: начни с учета исходников; не переноси сведения из других проектов.
- Только фото/3D, схемы, расчеты или аудит: выполняй соответствующий участок и его необходимые входные проверки.
- При неполных данных продолжай независимые участки; явно оставляй неподтвержденные связи и допущения.

## Обязательные рабочие правила

1. Учти каждый пользовательский снимок каждой папки. Сохрани путь, ID, хеш, этаж и статус. Дубликаты не исключай из учета. Просмотр контактного листа не называй детальным просмотром оригинала.
2. Создай реестр помещений по плану. Привязывай фото по дверям, окнам, соседству, отделке и другим наблюдаемым признакам. Два снимка на помещение подтверждай двумя реальными связями; не подменяй недостающие фото. Не переносись от «все фото в атласе» к «все комнаты восстановлены» без проверки.
3. Калибруй план по известным размерам. Записывай источник каждой высоты, толщины, координаты и масштаба. Без масштаба не объявляй точные метры. Не заменяй неизвестную геометрию художественным предположением.
4. Назначай пол и стены отдельно каждому помещению по его фотографиям. Сохраняй характерные голубые/зеленые и другие цвета, тип покрытия и меблировку. Отмечай визуальную оценку отдельно от измеренного цвета. Для числового смешивания сохраняй маски и параметры; не утверждай, что оно выполнено, если был только текстовый промпт.
5. Разделяй концептуальный AI-рендер и параметрическую BIM-модель. Настоящий BIM требует редактируемых пространственных объектов, ID и проверяемой геометрии; изображение или PDF не заменяет модель. Используй доступный геометрический инструмент для модели; при его отсутствии выпускай честно обозначенный концептуальный результат.
6. Генерируй/редактируй иллюстрации доступным imagegen по правилам среды. Для точных инженерных схем применяй векторное/программное построение, а не генерацию пикселей. Промпты составляй заново по фото и планам текущего проекта.
7. Выпускай отдельно инженерный план, топологию сети, питание, схему шкафа и кабельный журнал. Связывай их одними ID камер, AP, розеток, FD, трасс и источников питания. Показывай легенду, коробки, стояки, короба, соединения и резерв для датчиков.
8. Предлагай проводной, беспроводной и гибридный варианты. Беспроводная связь не означает отсутствия электропитания и всех кабелей. Проверяй конкретные модели Ajax, интерфейсы и совместимость с NVR по актуальным первичным источникам.
9. Разделяй камеры, документы, управление, сотрудников и гостей; составляй матрицу доступа. Предусматривай обслуживаемую серверную, два варианта бюджета, две NAS-конфигурации, VPN, резервирование и восстановление. Скрытый NAS должен иметь вентиляцию, питание, обслуживание и связь; не называй его облаком. Не обещай защиту от всего.
10. Считай трассы кодом по полилиниям с вертикалями, оконечными запасами, резервом и округлением; мощности, PoE, порты, энергию UPS, поток и архив — по явным формулам. Не используй исторические мощности/цены как новые паспортные факты. Проверяй текущие характеристики и цены при новом подборе.
11. Составляй смету с количеством, единицей, ценой, источником и датой. Отделяй общие позиции от альтернатив и ежемесячных расходов. Обновляй все зависимые суммы при изменении маршрутов/моделей.
12. Состав листов и формат зафиксируй по требованиям текущего объекта. Если пользователь задает шаблон, соблюдай его и проверяй размеры и читаемость печати.
13. Проверяй арифметику, полноту всех фото/помещений, ID, размеры листов и читаемость печати. Применяй PDF/документные навыки среды для верстки и визуальной проверки. Сохраняй редактируемые данные и конечные результаты.

## Исполнимые средства

Разрешай пути относительно каталога этого навыка. В облачной среде получи скрипты и данные через доступный механизм ресурсов навыка; не считай `skill://` локальным путем. Требуются Python; для контактов — Pillow. Это инструменты выполнения внутри сессии, не автономный облачный сервис.

```bash
python3 scripts/make_contacts.py /absolute/path/Pictures /absolute/path/new_contacts
```

Скрипт контактов по умолчанию ожидает папки `floor1`–`floor4` и `Outdoor`; для другого дерева адаптируй копию скрипта, сохранив полноту учета.



## Зависимости и честный статус

Доступ к изображениям, кодовому исполнителю, генерации, веб-источникам и формированию PDF предоставляет текущая среда. Плагин содержит навыки, справочники и Python-скрипты; не добавляет собственный BIM-движок, imagegen API или хостинг. При недоступности нужной возможности укажи конкретно заблокированный результат и продолжай остальные разрешенные части.

Для каждой команды сохраняй: `command_id`, `input_revision`, `output_files`, `checks`, `status`, `unresolved_items`. Статусы: `done_verified`, `done_with_assumptions`, `needs_input`, `failed`, `not_implemented`. Изменение исходника аннулирует зависимые расчеты и листы. Не показывай старый результат как новый.

При завершении выдавай файлы и статус готовности. Подробности, допущения и открытые вопросы помещай в отчет; короткое сообщение в чате не должно обещать отсутствующие возможности.
